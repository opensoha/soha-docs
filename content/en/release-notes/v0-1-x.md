# OpenSoha 0.1.x Releases

OpenSoha components use independent semantic versions. A release set records compatible artifacts; it does not require every repository, runtime image, npm package, or Helm chart to share one version number.

## Highlights

- Contracts `0.1.13` adds the workload snapshot schedule API and generated SDK surface.
- Core and Web add workload snapshot creation while retaining the hardened production workbench and independently pinned Web artifact.
- Agent `0.1.6` keeps Docker-only workers from polling general execution tasks and moves the release build to contracts `0.1.13`.
- Operator `0.1.0` introduces the `WorkloadCronJob` controller and publishes public `linux/amd64` and `linux/arm64` images through GHCR.
- Observability chart `0.2.0` adds authenticated OTLP ingestion and optional metrics and trace pipelines while preserving the logs-only default.
- CLI `0.1.6` adds cluster capability diagnostics, aligns npm metadata with the release tag, and moves to Go `1.26.6` to include current standard-library security fixes.

## Upgrade Order

1. Upgrade contracts consumers only after the contracts npm package and Go module tag resolve.
2. Verify the Web `v0.1.6` archive and checksum before embedding it into the Soha `v0.1.6` release.
3. Upgrade Agent and Operator independently. Their compatibility boundary is the public API or protocol, not matching SemVer values.
4. Upgrade Helm charts after their referenced GHCR images are available. A chart version and its `appVersion` intentionally have separate version sequences.

The Soha, CLI, Agent, and Hermes images use `v`-prefixed runtime tags. The Operator image uses `0.1.0` without a `v`; the Operator chart derives this tag from its `appVersion`.

## Rollback

- Roll back Soha with the matching control-plane image, embedded Web artifact, and contracts dependency.
- Roll back Web with both its dist archive and checksum sidecar.
- Roll back Agent, Hermes, or Operator by pinning the previous image and chart versions together.
- Published npm and Go module versions are immutable. Ship a forward patch instead of moving or unpublishing a public version.

## Verification

Release workflows verify checksums and downloaded release assets. Runtime images and Operator images are multi-architecture GHCR manifests. Helm publishing verifies referenced runtime images before creating GitHub Release packages, OCI charts, and the GitHub Pages index.
