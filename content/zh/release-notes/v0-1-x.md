# OpenSoha 0.1.x 发布说明

OpenSoha 各组件采用独立的语义化版本。一次发布组合用于记录彼此兼容的产物，不要求所有仓库、运行时镜像、npm 包和 Helm chart 使用同一个版本号。

## 主要变更

- Contracts `0.1.13` 新增 workload snapshot schedule API 与生成的 SDK 接口。
- Core 与 Web 新增 workload snapshot 创建能力，同时保留生产 workbench 加固和独立固定的 Web 产物。
- Agent `0.1.6` 防止仅启用 Docker 的 worker 误轮询通用 execution task，并将发布构建固定到 contracts `0.1.13`。
- Operator `0.1.0` 引入 `WorkloadCronJob` 控制器，并通过 GHCR 发布公开的 `linux/amd64` 与 `linux/arm64` 镜像。
- Observability chart `0.2.0` 新增带认证的 OTLP 接入，以及可选 metrics 和 traces 管道，同时保留默认的 logs-only 模式。
- CLI `0.1.6` 新增集群能力诊断，统一 npm 元数据与 release tag，并升级到 Go `1.26.6` 以包含当前标准库安全修复。

## 升级顺序

1. 只有在 contracts npm 包和 Go module tag 均可解析后，才升级 contracts consumer。
2. 在嵌入 Soha `v0.1.6` 前，先校验 Web `v0.1.6` 归档及其 checksum。
3. Agent 与 Operator 独立升级；兼容边界是公开 API 或协议，而不是相同的 SemVer。
4. 对应 GHCR 镜像可用后再升级 Helm chart。Chart 版本与 `appVersion` 有意采用各自独立的版本序列。

Soha、CLI、Agent 与 Hermes 镜像使用带 `v` 前缀的 runtime tag。Operator 镜像使用不带 `v` 的 `0.1.0`，Operator chart 从 `appVersion` 得到该 tag。

## 回滚

- 回滚 Soha 时，同时恢复匹配的控制面镜像、内嵌 Web 产物和 contracts 依赖。
- 回滚 Web 时，同时恢复 dist 归档与 checksum sidecar。
- 回滚 Agent、Hermes 或 Operator 时，同时固定上一版镜像与 chart。
- 已发布的 npm 与 Go module 版本不可变；应发布向前修复版本，不移动或撤销公开版本。

## 验证

发布流水线会校验 checksum 与重新下载的 release 资产。Runtime 与 Operator 镜像均为多架构 GHCR manifest。Helm 发布在创建 GitHub Release 包、OCI chart 和 GitHub Pages index 前，会先验证 chart 引用的 runtime 镜像。
