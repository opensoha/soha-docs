# OpenSoha 0.1.x 发布说明

OpenSoha 各组件采用独立的语义化版本。一次发布组合用于记录彼此兼容的公开产物，不要求所有仓库、运行时镜像、npm 包和 Helm chart 使用同一个版本号。

Core、Web、Contracts、CLI、Agent、Skills 和 Connectors 现已统一从主仓 [`opensoha/soha`](https://github.com/opensoha/soha) 按组件标签发布；[`opensoha/soha-operator`](https://github.com/opensoha/soha-operator) 与 [`opensoha/soha-helm`](https://github.com/opensoha/soha-helm) 继续保持独立仓库与发布周期。

## 主要变更

- **主仓统一发布**：六个原独立组件仓库（`soha-contracts`、`soha-web`、`soha-cli`、`soha-agent`、`soha-skills`、`soha-connectors`）已归档为只读历史源，后续组件版本统一从 `opensoha/soha` 发布，Web 控制台由 Core 发布工作流基于同提交源码构建并嵌入交付。
- **Contracts `0.2.0`**：启用 `github.com/opensoha/soha/contracts` Go 模块路径与 `@opensoha/contracts@0.2.0` npm 包，补充 `agent/dsh-runtime.schema.json`、虚拟机与工作区契约以及受控 CLI 会话端点定义。
- **Core `v0.1.13` 与 Agent `v0.2.0`**：合入统一内网访问运行时镜像、可选 `dsh` / Hindsight 配置入口（默认关闭）以及 `soha-dsh:v0.2.0`、`soha-docker-volume-reader:v0.2.0`、`soha-buildpacks-agent` 多架构镜像；Hermes runner 停止发布新镜像，既有镜像和可选运行入口保留。
- **CLI `v0.2.1`**：修复 npm 12 打包描述符校验并完成签名 npm 启动器、原生归档、Go 子模块与双架构镜像公开校验（`cli/v0.2.0` 仅发布了原生归档与容器镜像，未发布 npm 包，既有不可变产物保留）。
- **Operator `v0.1.1`**：更新 `WorkloadCronJob` 对账与源工作负载 / CronJob `resourceVersion` 状态记录，配套发布 `soha-operator` Helm chart `0.1.2`。

## 升级顺序

1. 只有在 `@opensoha/contracts` npm 包与 `github.com/opensoha/soha/contracts` Go 模块标签均可解析后，才升级下游组件或外部消费者。
2. Core `v0.1.13` 镜像与发行资产已内置同提交构建并校验的 Web 控制台产物；启用新 Chat / Heya 前需额外部署匹配的 `soha-dsh:v0.2.0` 并按 [Agent Runtime](./../operations/agent-runtime.md) 完成离线维护切换。
3. Agent、CLI 与 Operator 独立升级；兼容边界是公开 API、Agent 协议与能力矩阵，而不是相同的 SemVer 数字。
4. 对应 GHCR 镜像可用后再升级 Helm chart。Chart 版本与 `appVersion` 采用各自独立的版本序列；在新版 `soha` / `soha-agent` chart 发布前，不要假定 Helm 默认 `appVersion` 已自动指向 `v0.1.13` / `v0.2.0`。

Soha、CLI、Agent、DSH 与网络运行时镜像使用带 `v` 前缀的 runtime tag。Operator 同时发布 `vX.Y.Z` 与不带 `v` 的 `X.Y.Z` 镜像标签，原生清单与 Operator chart 从 `appVersion` 使用不带 `v` 的 `0.1.1`。

## 回滚

- 回滚 Soha 时，同时恢复匹配的 Core 镜像（及其内嵌 Web 产物）、网络运行时镜像和数据库兼容范围；已启用加密检查点时保留有效凭据加密密钥。
- 回滚 Agent、DSH、Hermes 或 Operator 时，同时固定上一版已验证镜像与匹配的清单或 chart 版本。
- 已发布的 npm 包、Go module 版本和 GHCR 发布标签不可变；出现问题时发布向前补丁版本（例如 `cli/v0.2.1`），不移动标签或覆盖已公开产物。

## 验证与历史归档说明

`soha-web-dist.tar.gz` 与 Web 摘要保存在发布工作流的 Actions 构建产物中，不是 `v0.1.13` 的独立 GitHub Release 下载附件。公开 manifest 记录同提交 Web 的摘要，使用发行二进制或镜像即可获得内嵌控制台。

发布流水线会校验源码提交绑定、checksum、签名 provenance 与重新下载的公开资产；Core、Agent、CLI 与 Operator 关键运行镜像提供 GHCR 多架构 manifest（`soha-proxy-v2ray` 与 `soha-radius` 当前仅构建 `linux/amd64`）。

2026 年 8 月早期组合（Contracts `0.1.13`、Core / Web / CLI / Agent `v0.1.6`、Operator `v0.1.0`、Skills `v0.1.1`）的原始标签与资产字节已保全在主仓历史归档中；原独立组件仓库归档退役后，历史旧仓库 URL 与旧 Go 模块路径可能停止解析，新安装与固定版本应统一使用上表中的 `opensoha/soha` 与 `opensoha/soha-operator` 产物。
